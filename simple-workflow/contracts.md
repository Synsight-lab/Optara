# Contracts

This file specifies `OptionSeriesFactory` and `OptionSeriesVault`. The oracle library is in [oracle.md](./oracle.md) and the guard is in [premium-guard.md](./premium-guard.md). Formulas are in [math.md](./math.md).

## Design Rule

```text
A value that must be fixed or derived is never a function argument.
The contract computes it or reads it from its own immutable state.
```

Series identity, collateral asset, scales, `collateralPerOption` and fee rates are computed or snapshotted at creation. A caller can never choose them.

## Shared Types

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

uint256 constant PRICE_SCALE = 1e18;
uint256 constant BPS_SCALE = 10_000;

uint16 constant MAX_MINT_FEE_BPS = 100;       // 1.00%, compile-time cap
uint16 constant MAX_EXERCISE_FEE_BPS = 100;   // 1.00%, compile-time cap

// Series creation limits. Fixed in code so no user can choose them.
uint64  constant MIN_EXPIRY_DELAY = 1 hours;
uint64  constant MAX_EXPIRY_DELAY = 30 days;       // "for now"; raise in a later version
uint64  constant EXPIRY_SLOT_OFFSET = 8 hours;     // expiry must fall at 08:00 UTC on some day
uint8   constant OPTION_DECIMALS = 18;             // every option token has 18 decimals
uint256 constant MIN_OPTION_AMOUNT = 1e16;         // 0.01 option, mint only

enum OptionType { CALL, PUT }

struct FeeConfig {
    uint16 mintFeeBps;
    uint16 exerciseFeeBps;
}

/// The ONLY things a user chooses when creating a series.
struct CreateSeriesParams {
    OptionType optionType;
    address underlying;
    address quote;
    uint256 strikePrice;            // PRICE_SCALE: whole quote per whole underlying, times 1e18
    uint64 expiry;                  // unix seconds, at most 30 days out, on the 08:00 UTC slot
    address chainlinkFeed;          // must equal the ADMIN-approved feed for this pair
}

/// Set by ADMIN for each (underlying, quote) pair. Users cannot choose these.
struct PairConfig {
    address feed;                   // the one approved Chainlink feed, address(0) = pair disabled
    uint32 maxChainlinkAgeAtExpiry; // seconds, heartbeat plus a buffer, see oracle.md
    uint256 strikeStep;             // strike must be a multiple of this, PRICE_SCALE units
}

/// The complete, fixed definition of a series, assembled by the factory and passed to the vault.
struct SeriesConfig {
    OptionType optionType;
    address underlying;
    address quote;
    uint256 strikePrice;
    uint64 expiry;
    uint256 contractSize;           // 10 ** underlyingDecimals: exactly one whole underlying per option
    uint8 optionDecimals;           // OPTION_DECIMALS
    uint256 minOptionAmount;        // MIN_OPTION_AMOUNT
    uint256 maxTotalShortAmount;    // snapshot of the underlying's cap, 0 = uncapped
    address chainlinkFeed;
    uint32 maxChainlinkAgeAtExpiry; // snapshot of the pair's value
    string name;                    // generated by the factory
    string symbol;                  // generated by the factory
}

/// What the vault reports about itself. Read by the guard and the frontend.
struct SeriesInfo {
    bytes32 seriesId;
    OptionType optionType;
    address underlying;
    address quote;
    address collateralAsset;
    uint256 strikePrice;
    uint64 expiry;
    uint256 contractSize;
    uint8 optionDecimals;
    uint256 minOptionAmount;
    uint256 maxTotalShortAmount;
    address chainlinkFeed;
    uint8 feedDecimals;
    uint32 maxChainlinkAgeAtExpiry;
    uint256 optionScale;
    uint256 uqScale;
    uint256 collateralPerOption;
    uint16 mintFeeBps;
    uint16 exerciseFeeBps;
}

struct SettlementProof {
    uint80 chainlinkRoundId;        // the round in force at expiry
    uint80 chainlinkNextRoundId;    // its immediate successor
}
```

## Roles

Exactly two, held on the factory using OpenZeppelin `AccessControl`. Vaults and the guard ask the factory `hasRole(...)`, so no vault keeps its own role state. **There is no creator role: anyone can create a series** within the limits below.

| Role | Held by | Can do |
|---|---|---|
| `ADMIN` (`DEFAULT_ADMIN_ROLE`) | multisig or timelock | Allowlist assets, approve the Chainlink feed for each pair (and its age window and strike step), set the per-underlying open-interest cap, set default fees for **future** series, set the fee recipient, set a series' Kuru market pointer (once), sweep accrued fees, set guard parameters, grant and revoke roles. Can **freeze** and **unfreeze** minting on any series and series creation. |
| `PAUSER` | guardian | Can **freeze** (pause) minting on any series and freeze series creation. **Cannot unfreeze.** |

Role ids: `ADMIN = DEFAULT_ADMIN_ROLE` (0x00), `PAUSER = keccak256("PAUSER_ROLE")`.

No role can move collateral, change a series after creation, change a fee rate on a live series, change a settlement result, or stop `settle`, `redeem`, `claimWriterResidual`, `payout` or ERC-20 transfers.

`ADMIN` can move `accruedFees` and nothing else.

## `OptionSeriesFactory`

The canonical registry, and the holder of roles and global settings.

### Storage

```solidity
mapping(address => bool) public allowedAsset;
mapping(bytes32 => PairConfig) public pairConfig;   // key = keccak256(abi.encode(underlying, quote))
mapping(address => uint256) public maxShortAmountOf; // per underlying, option raw units, 0 = uncapped
FeeConfig public defaultFeeConfig;            // snapshotted into each NEW series
address public feeRecipient;                  // read live at sweep time, never snapshotted

bool public creationPaused;
uint256 public seriesCount;                   // used only to generate names

mapping(bytes32 => address) public vaultOf;   // seriesId -> vault
mapping(address => bytes32) public seriesIdOf;// vault -> seriesId, nonzero means official
mapping(bytes32 => address) public kuruMarketOf; // write-once pointer, optional
```

### Functions

```solidity
    external returns (bytes32 seriesId, address vault);     // ANYONE

function setAllowedAsset(address asset, bool allowed) external;                       // ADMIN

```

### `createSeries`

Callable by **anyone**. The user chooses only the option type, the two assets, the strike, the expiry and the feed. Everything else is fixed by the factory or by `ADMIN`. It reverts if any of these fail:

- Creation is paused (`CreationPaused`).
- `underlying` or `quote` is zero, or they are equal.
- Either asset is not allowlisted (`AssetNotAllowed`).
- Either asset's `decimals()` cannot be read or exceeds 18.
- **Feed check.** `pairConfig[pairKey(underlying, quote)].feed` is zero (pair disabled), or `p.chainlinkFeed` is not exactly that address (`FeedNotApproved`).
- **Strike.** `strikePrice == 0` or `strikePrice % strikeStep != 0` (`InvalidStrike`).
- **Expiry.** `expiry < block.timestamp + MIN_EXPIRY_DELAY`, `expiry > block.timestamp + MAX_EXPIRY_DELAY` (30 days), or `expiry % 1 days != EXPIRY_SLOT_OFFSET` (`InvalidExpiry`).
- Either default fee exceeds its cap (`FeeExceedsCap`).
- **The series already exists** (`DuplicateSeries(seriesId)`). There is no idempotent return: a second creation with the same identity always reverts.

`seriesId`:

```solidity
seriesId = keccak256(abi.encode(
    block.chainid,
    address(this),
    optionType,
    underlying,
    quote,
    strikePrice,
    expiry,
    chainlinkFeed
));
```

**Fixed by the factory** (the user cannot change them):

| Field | Value |
|---|---|
| `contractSize` | `10 ** underlyingDecimals`: one whole underlying per option |
| `optionDecimals` | `OPTION_DECIMALS` (18) |
| `minOptionAmount` | `MIN_OPTION_AMOUNT` (0.01 option) |
| `maxTotalShortAmount` | `maxShortAmountOf[underlying]`, snapshotted |
| `maxChainlinkAgeAtExpiry` | `pairConfig.maxChainlinkAgeAtExpiry`, snapshotted |
| fee rates | copy of `defaultFeeConfig`, snapshotted |
| `name` / `symbol` | `"Optara Option #N"` / `"OPT-N"`, where `N = ++seriesCount` |

Names are generic on purpose. Nothing a user types ends up in token metadata, so there is nothing to squat or fake. Frontends show a series' real details from `seriesInfo()`, never from the name.

The factory then does `new OptionSeriesVault(...)` with a `SeriesConfig`, the `seriesId`, its own address and the fee copy, stores both mappings, and emits `SeriesCreated`. The vault derives everything else itself.

**Why this stays safe without a trusted creator.**

- The only thing a wrong parameter could break is the feed, and the user cannot pick a feed the factory does not already know. `ADMIN` approves exactly one feed per pair after two people confirm it, so a user typing a wrong address just gets `FeedNotApproved`.
- `maxChainlinkAgeAtExpiry` is not user-controlled, because a user could set it huge to accept a dead feed or tiny to make the series unsettleable.
- Front-running is harmless. If someone creates the identical series first, the second call reverts and the user simply mints into the existing one.
- **Series spam.** Anyone can create series, and each creation costs its creator a vault deployment. The expiry slot, the 30-day limit and the strike step bound the number of possible series per pair to roughly (30 expiries) × (strikes on the step grid) × 2 option types. The frontend should list only series that have open interest or a Kuru market. Spam clutters a list but cannot touch anyone's funds.
- `PAUSER` can stop creation instantly if a bad feed is approved.

### `setPairConfig`

`ADMIN` only. Both assets must be allowlisted. Reverts with `InvalidOracleConfig` if the feed's `decimals()` cannot be read or exceeds 18, if `latestRoundData()` does not return a positive answer, or if `maxChainlinkAgeAtExpiry == 0` or `strikeStep == 0`. Setting `feed = address(0)` disables the pair for new series.

Changing a pair's feed or age affects **only series created afterward**. Every existing series keeps the feed and age it was created with. Approving a feed is the security-critical decision in the system: two people confirm that the feed is a direct feed for exactly that pair before `ADMIN` sets it.

### Asset allowlist

`ADMIN` allowlists an asset only after confirming that it is a standard ERC-20, non-rebasing, charges no transfer fee, has no re-entering transfer hooks, and has stable, readable decimals. The vault does not measure balance deltas, so this allowlist is the only defense against fee-on-transfer and rebasing tokens. Native MON is excluded. Use WMON.

### `setKuruMarket`

Stores an optional pointer from a `seriesId` to its official Kuru market. It is write-once. The contracts never call Kuru. The pointer exists so the guard and the frontend can tell which market is official. The factory does not validate the market on chain. The frontend must confirm that its base asset is the vault and its quote asset is the series quote before `ADMIN` sets it.

Because series are now permissionless, `ADMIN` should set this only for series that have a market worth linking. The pointer is convenience, never required.

### Size

The factory embeds the vault's creation code. Check the deployed factory against the chain's contract size limit before deployment. If it is too large, move `new OptionSeriesVault` into a small separate `VaultDeployer` contract that only the factory may call.

## `OptionSeriesVault`

One per series. It is the ERC-20 option token and the holder of collateral. Built on `ERC20`, `ReentrancyGuard`.

### Constructor

```solidity
constructor(
    address factory_,
    bytes32 seriesId_,
    SeriesConfig memory p,
    FeeConfig memory fees
) ERC20(p.name, p.symbol)
```

It derives and stores as `immutable`:

- `collateralAsset` (underlying for a call, quote for a put).
- `optionScale`, `uqScale` (from the two assets' `decimals()`), `collateralPerOption`.
- `feedDecimals` (from `chainlinkFeed.decimals()`).
- `mintFeeBps`, `exerciseFeeBps`.

It reverts if `requiredCollateral(minOptionAmount) == 0` (`InvalidMinOptionAmount`), if `uqScale == 0`, or if any input is invalid. `decimals()` is overridden to return `optionDecimals`.

Because vaults are plain deployments, every series parameter is an `immutable` and there is no initializer and no setter.

### Storage

```solidity
bool public settled;
bool public mintPaused;

uint256 public totalShortAmount;
uint256 public totalUnclaimedShortAmount;
uint256 public collateralLocked;
uint256 public accruedFees;                 // segregated from collateralLocked
uint256 public totalBuyerPayoutClaimed;
uint256 public totalWriterResidualClaimed;

uint256 public settlementPrice;             // PRICE_SCALE, write-once
uint256 public buyerPayoutRate;             // collateral raw per whole option, write-once
uint256 public writerResidualRate;          // collateral raw per whole option, write-once
uint64  public settledAt;

mapping(address => uint256) public writerShortBalance;
```

There are only two states: not settled and settled. Expiry is derived from `block.timestamp >= expiry`, never written.

### Function permissions

| Function | Before expiry | After expiry, not settled | After settlement |
|---|---|---|---|
| `mint` | allowed (if not paused) | reverts | reverts |
| ERC-20 transfer | allowed | allowed | allowed |
| `settle` | reverts | allowed | reverts `AlreadySettled` |
| `redeem` | reverts | reverts | allowed |
| `claimWriterResidual` | reverts | reverts | allowed |
| `payout` (anyone) | reverts | reverts | allowed |
| `sweepFees` (`ADMIN`) | allowed | allowed | allowed |
| `setMintPaused` (freeze: `PAUSER` or `ADMIN`; unfreeze: `ADMIN`) | allowed | allowed | allowed |

Paused minting does not affect any other function. No flag can stop settle, redeem, claim, transfer or sweep.

Payouts are **pull-based**: `redeem` and `claimWriterResidual` are called by their owners. One optional function, `payout`, lets a keeper trigger the same payouts for a list of accounts. The vault never pushes payouts inside `settle`.

### `mint(optionAmount, receiver)`

```solidity
function mint(uint256 optionAmount, address receiver)
    external nonReentrant returns (uint256 collateralAmount, uint256 feeAmount);
```

Reverts if: minting is paused, `block.timestamp >= expiry`, `optionAmount < minOptionAmount`, `maxTotalShortAmount != 0 && totalShortAmount + optionAmount > maxTotalShortAmount` (`OpenInterestCapExceeded`), `receiver == address(0)`, or the required collateral is zero.

```text
collateralAmount = ceilDiv(optionAmount * collateralPerOption, optionScale)
feeAmount        = ceilDiv(collateralAmount * mintFeeBps, BPS_SCALE)
writer transfers   collateralAmount + feeAmount
```

Execution order (normative):

1. Validate inputs and state.
2. Compute `collateralAmount` and `feeAmount`.
3. `writerShortBalance[msg.sender] += optionAmount`.
4. `totalShortAmount += optionAmount`.
5. `totalUnclaimedShortAmount += optionAmount`.
6. `collateralLocked += collateralAmount`.
7. `accruedFees += feeAmount`.
8. Emit `OptionsMinted`.
9. `safeTransferFrom(collateralAsset, msg.sender, this, collateralAmount + feeAmount)`.
10. `_mint(receiver, optionAmount)`.

The short position belongs to `msg.sender`. The tokens go to `receiver`.

### `settle(proof)`

```solidity
function settle(SettlementProof calldata proof) external nonReentrant returns (uint256 price);
```

Anyone may call it. Not payable. Reverts if: `block.timestamp < expiry`, already settled, or the oracle library rejects the proof (see `oracle.md`).

1. `price = ChainlinkAnchor.priceAtExpiry(...)`, normalized to `PRICE_SCALE`.
2. Compute `buyerPayoutRate` from the call or put formula in `math.md`, rounding down.
3. `writerResidualRate = collateralPerOption - buyerPayoutRate` (subtraction only).
4. Write `settlementPrice`, both rates, `settledAt`, then `settled = true`.
5. Emit `SeriesSettled`.

The price does not depend on who calls or when. Settling minutes after expiry and months after produce the same result.

### `redeem(optionAmount, receiver)`

```solidity
function redeem(uint256 optionAmount, address receiver)
    external nonReentrant returns (uint256 payoutAmount, uint256 feeAmount);
```

Reverts if: not settled, `optionAmount == 0`, or `receiver == address(0)`. The burn reverts if the caller's balance is too small. There is no minimum size here.

```text
grossPayout  = floor(optionAmount * buyerPayoutRate / optionScale)
feeAmount    = floor(grossPayout * exerciseFeeBps / BPS_SCALE)
payoutAmount = grossPayout - feeAmount
```

Execution order:

1. Validate.
2. Compute `grossPayout`, `feeAmount`, `payoutAmount`.
3. `_burn(msg.sender, optionAmount)`.
4. `collateralLocked -= grossPayout`.
5. `accruedFees += feeAmount`.
6. `totalBuyerPayoutClaimed += grossPayout`.
7. Emit `OptionsRedeemed`.
8. If `payoutAmount > 0`: `safeTransfer(collateralAsset, receiver, payoutAmount)`.

`collateralLocked` drops by the gross amount while only the net leaves the vault. The difference stays as accrued fees, so `balanceOf(vault) >= collateralLocked + accruedFees` stays exact. An out-of-the-money redemption burns, pays nothing and charges no fee, so holders can always clear worthless balances.

### `claimWriterResidual(shortAmount, receiver)`

```solidity
function claimWriterResidual(uint256 shortAmount, address receiver)
    external nonReentrant returns (uint256 residualAmount);
```

Reverts if: not settled, `shortAmount == 0`, `shortAmount > writerShortBalance[msg.sender]`, or `receiver == address(0)`.

```text
residualAmount = floor(shortAmount * writerResidualRate / optionScale)
```

1. Validate.
2. Compute `residualAmount`.
3. `writerShortBalance[msg.sender] -= shortAmount`.
4. `totalUnclaimedShortAmount -= shortAmount`.
5. `collateralLocked -= residualAmount`.
6. `totalWriterResidualClaimed += residualAmount`.
7. Emit `WriterResidualClaimed`.
8. If `residualAmount > 0`: `safeTransfer(collateralAsset, receiver, residualAmount)`.

No fee is charged here. The writer paid at mint.

### `payout(accounts)`: keeper payout for everyone

After settlement, one permissionless function pays a list of accounts what they are owed. It reads each account's balances itself, so no per-account data is stored.

```solidity
function payout(address[] calldata accounts) external;            // anyone, after settlement
function payAccount(address account) external;                    // only callable by the vault itself
```

`payout` reverts with `NotSettled` before settlement. For each account it does `try this.payAccount(account) {} catch {}`. `payAccount` is `nonReentrant`, reverts with `Unauthorized` unless `msg.sender == address(this)`, and does the following:

1. If `account == address(0)` or `account.code.length > 0`, do nothing (see below).
2. If `balanceOf(account) > 0`, redeem the **entire** balance to `account`, exactly as `redeem(balance, account)` would, including the exercise fee, accounting and `OptionsRedeemed` event.
3. If `writerShortBalance[account] > 0`, claim the **entire** short balance to `account`, exactly as `claimWriterResidual(short, account)` would, including the `WriterResidualClaimed` event.

An account that is both a holder and a writer gets both. An account owed nothing is a no-op. A duplicate in the list is a no-op the second time.

Design points:

- **Everyone in one call, and never blocking.** Each account runs in its own guarded self-call inside `try/catch`, so one that fails is skipped and rolled back and the rest still pay. Allowlisted tokens have no transfer hooks, so a recipient cannot run code or burn gas. The only thing that can fail an account is the token itself, for example a blacklisted USDC address.
- **The keeper supplies the list, the vault supplies the amounts.** The contract cannot enumerate holders, so the keeper builds the list off chain from `Transfer` and `OptionsMinted` events. Balances and short positions are read live inside the call. No opt-in and no amounts are passed in.
- **Payouts always go to the account, never to the caller.** Full balance only, so nobody can burn a holder's value by redeeming tiny chunks that round to zero.
- **Contracts are skipped.** A contract may hold option tokens on behalf of other people, for example a Kuru order book with users' resting asks. Redeeming those tokens without that contract's knowledge would break its accounting and strand users. So `payout` only pays accounts with no code. Contracts, including smart-contract wallets and any contract writer, call `redeem` and `claimWriterResidual` themselves. Wallets and smart accounts that have code are never redeemed on their owner's behalf.
- **Batch size.** The caller chooses how many accounts per call, so gas is bounded by the caller and not by the vault.
- **Payouts never depend on the keeper.** Owners can always call `redeem` and `claimWriterResidual` themselves.
- A holder's payout is fixed once settlement is written, so an early redemption costs a holder no choice. The fee is the same.
- Tokens inside a Kuru order or margin account are held by Kuru, not by the trader, so `payout` skips them. The trader must withdraw them first.

### `sweepFees()`

```solidity
function sweepFees() external nonReentrant returns (uint256 amount);   // ADMIN only
```

Reverts with `NoFeesAccrued` if `accruedFees == 0`, or `ZeroAddress` if the fee recipient is zero. It takes **no receiver argument**. It sends to `factory.feeRecipient()`, read live, so rotating a compromised treasury address works and the admin cannot redirect fees.

1. `receiver = factory.feeRecipient()`.
2. `amount = accruedFees`; `accruedFees = 0`.
3. Emit `FeesSwept`.
4. `safeTransfer(collateralAsset, receiver, amount)`.

It never reads or reduces `collateralLocked`. It works in every state.

### `setMintPaused(bool)` and freezing a series

```solidity
function setMintPaused(bool paused) external;
```

- **Freezing** (`paused = true`) can be done by `PAUSER` or `ADMIN`.
- **Unfreezing** (`paused = false`) can be done by `ADMIN` only.

Emits `MintPauseSet(paused)`. This is the tool for a series that looks malicious or wrong but passed every check, for example one attached to a feed that later turns out to be wrong. It stops **new deposits** immediately.

**What a freeze does.** It blocks `mint` on that one series and nothing else.

**What a freeze can never do.** It cannot block `settle`, `redeem`, `claimWriterResidual`, `payout`, `sweepFees` or ERC-20 transfers, and it cannot change the series, its feed or its fees. Existing positions run to settlement exactly as before. This is deliberate. A freeze that could stop settlement or payouts would let a compromised or mistaken admin trap everyone's collateral, which breaks the core promise of the protocol.

**What a freeze does not fix.** Collateral already deposited in a bad series stays there until settlement, and it settles at whatever the series' feed reports. A freeze prevents more people from depositing. It does not rescue people who already have. That is why approving the feed is the critical decision, why early caps are low, and why a recovery path is an open founder decision (D9). Series creation has the same rule: `setCreationPaused` freezes new series, and unfreezing needs `ADMIN`.

A frozen series is visible on chain (`mintPaused == true`). Frontends should mark it clearly and stop offering it for minting.

## Fees

Two protocol fees, nothing else.

| Fee | When | Who pays | Rate | Rounding |
|---|---|---|---|---|
| Mint fee | `mint` | writer, **on top of** collateral | `mintFeeBps` | up |
| Exercise fee | `redeem`, in-the-money only | holder, carved from the gross payout | `exerciseFeeBps` | down |

- Rates are copied from `factory.defaultFeeConfig()` when a series is created and are `immutable` for its life. A later change to the defaults reaches only later series.
- Caps are compile-time constants: 100 bps each.
- Fees accrue into `accruedFees` and are swept on demand. There is no transfer to a fee recipient inside mint, redeem or claim, so a bad recipient can never brick those paths.
- No fee on writer residual claims.
- With both rates at zero, results are bit-identical to a no-fee vault. This is a fuzz target.
- Kuru's own fees are separate and never Optara revenue. See `premium-guard.md`.

## Accounting Relationships

Before settlement:

```text
totalSupply() == totalShortAmount
sum(writerShortBalance) == totalShortAmount == totalUnclaimedShortAmount
collateralLocked >= requiredCollateral(totalShortAmount)
```

Always:

```text
collateralAsset.balanceOf(vault) >= collateralLocked + accruedFees
```

After redemptions and claims (gross amounts):

```text
totalBuyerPayoutClaimed + totalWriterResidualClaimed + collateralLocked == total collateral ever locked
```

Nothing iterates over writers or holders. Every claim is pulled by its owner.

## Implementation Notes

- `redeem` and `payAccount` share one internal function taking `(holder, receiver, amount)`, and `claimWriterResidual` and `payAccount` share another, so the accounting exists once. The public functions only decide who the holder and receiver are.
- Every function that moves tokens is `nonReentrant` and follows: validate, update accounting, emit, external call last.
- `_mint` is the last step of `mint`, so an ERC-20 hook on the option token itself sees fully updated state.
- Use `SafeERC20` for all collateral transfers. Skip a transfer entirely when the amount is zero.
- Use `Math.mulDiv` with explicit rounding for every multiply-then-divide.
- Do not implement balance-delta accounting. The asset allowlist is the control.
- The vault holds no native token and has no `receive`.
